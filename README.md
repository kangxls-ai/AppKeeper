# AppKeeper

AppKeeper 是 Windows 10/11 x64 的应用启动器。半透明窗口采用 Launchpad 风格的分页图标网格。

左侧可切换「快捷应用」「最近访问」「飞鸽传书」和「日程管理」。标题栏提供最小化、最大化、还原和隐藏操作。普通窗口可拖动标题栏移动、拖右下角调整尺寸，最小宽度为 300 个逻辑像素。

## 最近访问

左侧是滚动七天的高频前 50 项，右侧按最近时间显示系统最近文件和运行期间观察到的文件夹访问。支持最近 7 天、30 天（默认）、全部记录，以及文件／文件夹、名称拼音和路径搜索。窄窗口自动切换为「七天高频」「最近记录」页签。单击打开，右键可打开所在位置、复制路径、隐藏单条、排除文件夹及其子目录。勾选多条后可批量隐藏。

首次导入与每次重启的系统历史只用于展示，不补算过去的访问次数。运行期间每 3 秒检查 Windows Recent 快捷方式变化和资源管理器公开的文件夹路径，合并五秒内同一路径的重复通知；关闭期间、快速跳转或不写入系统记录的应用可能漏记。文件夹首次基线不推断访问时间。排行显示可识别的次数，不代表完整的系统审计日志，打开文件不会自动给其父文件夹累计次数。

「管理」可暂停记录、恢复隐藏项、管理排除文件夹，或清空本应用保存的记录与排行。清空后旧系统历史不会立即重新导入，新访问可重新出现。所有操作仅影响本应用的数据，不删除实际文件，不清理或更改 Windows 历史设置。系统最近项目关闭或被策略禁止时暂停系统采集，管理页提供 Windows 设置入口和说明，由用户自行决定开启。

记录保存在 `AppKeeper.recent.json`，自动保留上次有效备份。绿色版保存于程序目录，商店版保存于自己的用户数据目录；首次从绿色版迁移时一并复制。布局的导入导出不包含此独立记录文件，完整迁移请退出程序后复制数据目录。

## 飞鸽传书

- 两台电脑运行 AppKeeper 后，可在局域网发现对方，或手动输入 IPv4 地址和通信端口。默认通信端口是 TCP 48620，自动发现使用 UDP 48619。通常应在 Windows 防火墙中只允许专用网络访问。确认配对前请核对双方显示的六位校验码。
- 配对后才能聊天或收发文件。对方离线时，文字存入本机队列，双方重新在线后依次发送。历史保存在本机。文件和文件夹可拖入或多选，文件夹先打包成 ZIP。传输中断会保留已有内容，重新连通后从已有字节继续，并在接收完成后校验文件。
- 配对时双方可各自授权自动接收，默认关闭。设置下可改接收目录和单项上限（默认 1 GB）。超过上限仍可逐项接受或拒绝。默认写入 EXE 同目录下的 `share`，接收的 ZIP 保持原样。

## 日程管理（MarkDo）

- 待办、月历、已完成和设置位于 AppKeeper 窗口内。可快速添加、补充计划和标签、记录开始和完成、填写投入和评分、查看提醒、按日期导出 Markdown。
- 默认使用程序目录下的独立日程数据库。要沿用原版 MarkDo 的数据，请在「日程管理 → 设置 → 打开现有 MarkDo 数据库」中选择 `markdo.db`。AppKeeper 会直接读取和写入该库，首次采用前可备份原文件。
- AppKeeper 直接提供原 MarkDo 手机端的配对与局域网双向同步，不需要同时运行原版 Windows MarkDo。进入「日程管理 → 连接手机」，显示二维码和六位确认码，再在原 MarkDo Android 手机端扫码或手动输入电脑 IP、端口与确认码。兼容原仓库 0.5.2 的加密同步协议 v4；更旧协议会提示升级。手机按原逻辑每约 8 秒同步，也可在手机点击「立即同步」。电脑隐藏到托盘后继续服务。
- 服务默认 TCP 8787，可在连接手机页立即修改或关闭，列出可用的局域网 IPv4。端口变化后重新配对手机。二维码五分钟有效、单次使用，二维码和手动输入共用八次确认尝试上限。多部手机分别配对，使用各自的密钥，通过电脑合并创建、修改、开始、完成、反馈、重新打开和删除等操作；离线修改在下次连接合并，重复操作按 ID 去重，按 clock、device_id、id 确定顺序。
- 同步使用原 MarkDo 的 AES-256-GCM 消息格式；手动配对通过 X25519 协商临时秘密。配对凭据使用当前 Windows 用户的 DPAPI 加密，保存在 `AppKeeper.agenda-sync.json` 并保留上次有效备份。连接页显示各手机上次连接和整体同步时间，可撤销配对，手机和电脑的本地任务会保留。服务只接受局域网或本机连接，不自动修改 Windows 防火墙；如 Windows 提示网络访问，请自行按需允许专用网络。
- 本次不导入独立 MarkDo 的历史任务或旧配对凭据。直接在 AppKeeper 与手机重新配对，现有 AppKeeper 日程会保留，并按协议与手机当前数据合并。配对凭据受 Windows 用户保护，切换 Windows 用户或电脑后需重新配对。

兼容实现对照原仓库提交 `0674d138ed442ee5e14380081bd7f365102254a7` 的 `lib/lan_sync.dart`、`lib/pairing.dart` 与 `lib/models.dart`。独立 Node/OpenSSL 互通检查位于 `tests/markdo-interop.mjs`，不依赖本实现的加密函数，覆盖扫码与手动配对、多手机合并、重放、错误码锁定、事务回滚、重启和撤销等。真实 Android 手机的相机扫码与 Wi-Fi 连接仍需实机验证。

## 使用

1. 在 [Actions](https://github.com/kangxls-ai/AppKeeper/actions) 打开成功的构建，下载 `AppKeeper-win-x64`，解压后将 `AppKeeper.exe` 放进可写目录运行。
2. 从托盘、桌面浮球或用 `Alt + Space` 呼出居中窗口。拖动标题栏可移动窗口，拖动边框或右下角可改变大小，最小宽度为 300 个逻辑像素。如果快捷键冲突，在设置中录入新组合。按 `Esc`、点击右上角 × 或点击应用区空白处可隐藏。
3. 在「待整理」查看从开始菜单、Win32 App Paths 和 Windows AppsFolder 自动发现的入口。右键可移到应用页、重命名、更换图标或移除。路径失效和已卸载的入口仍留在原位并标记不可用。
4. 拖到图标左右边缘排序，拖到中央创建文件夹或加入现有文件夹。拖至窗口左右边缘可翻页。从文件夹把图标拖到面板外会露出应用页，松手即可移出。也可放到面板下方的「拖到这里移出文件夹」。
5. 单击图标启动，单击分组打开原页上的文件夹面板。使用「添加」或从资源管理器拖入文件、快捷方式和文件夹。网址可通过「添加」录入。

登录自启动默认开启，可在设置中关闭。托盘菜单提供退出和重新扫描。程序使用独立的应用入口，整理操作只写入 AppKeeper 的数据文件。

浮球可在桌面上拖动，贴近屏幕工作区边缘松手后露出约四成，悬停立即打开应用主页。

搜索框下方可新建、筛选和拖拽排序标签。「全部」固定在首位。选中标签后，拖入文件、文件夹、快捷方式或通过「添加」新建入口，会自动关联当前标签。也可以把已有入口直接拖到目标标签，或在入口右键菜单中勾选多个标签。中文、全拼和首字母搜索可与标签同时使用。

每个标签中的入口顺序独立保存，与「全部」以及其他标签互不影响。清空搜索后，在标签页拖到图标左半边或右半边插入排序，拖到空白处放到该标签末尾，可拖至窗口边缘翻页。标签页内拖拽排序不会创建分组或改变原有分组关系。新关联的入口追加到标签末尾；顺序随配置备份、导入和商店版迁移保留。旧配置自动以升级时的顺序初始化每个标签，之后独立排序。

搜索框右侧显示最近 10 条检索，点击可重复筛选。下方的「最近访问」显示最多 20 个入口，右键可锁定或取消锁定。锁定项排在最前，剩余位置按访问时间排列。两行均可横向滚动。右键可单独清除记录，快捷应用右上角的历史按钮可批量清理，锁定的访问项会保留。拖动窗口右下角调整大小后，重启恢复上一次的普通窗口尺寸。

飞鸽传书可输入 2,000 字符，按 Enter 发送，按 Shift+Enter 换行。双击聊天中的文件名可用系统默认应用打开文件（包括 ZIP），也可打开文件所在文件夹。发送文件夹时保留生成的 ZIP，清空该对话的已结束记录时移除生成的 ZIP，原始文件和收到的文件会保留。

## 备份和迁移

`AppKeeper.data.json` 和 `AppKeeper.data.json.bak` 与 EXE 同目录。每次保存会保留上一份有效配置。主文件损坏时会尝试从备份恢复。设置中的导出文件包含分组、排序、快捷键及自定义图标。可导入此文件，或先退出 AppKeeper 后复制整个目录，再从新位置运行。

## 构建

Microsoft Store 版使用 EasyAppKeeper 名称。其 MSIX 构建、提交和从绿色版迁移的步骤见 [商店版说明](packaging/store/README.md)。

需要 .NET 10 SDK。Windows Actions 在推送、拉取请求及手动运行时编译、自检并上传 x64 产物。也可在本地运行：

```powershell
dotnet publish src/AppKeeper/AppKeeper.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false -o artifacts/win-x64
```

自检覆盖 500 个入口的拼音搜索、分组与排序、扫描合并、备份恢复及导出验证。手工验收步骤见 [验收清单](ACCEPTANCE.md)。

拼音数据来源为 [Unicode 16.0 Unihan](https://www.unicode.org/Public/16.0.0/ucd/Unihan.zip) 的 `kMandarin` 和 `kHanyuPinyin`，许可随项目和 EXE 提供。拼音检索使用单字读音及其组合。
